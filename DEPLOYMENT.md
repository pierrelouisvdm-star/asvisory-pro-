# Deploying to advisorypro.co.za

Backend on Render, frontend on Vercel, database on MongoDB Atlas. No
Emergent involved — everything below is usage-based pricing per provider.

## 1. Database — MongoDB Atlas

1. Create a free (M0) cluster at https://cloud.mongodb.com.
2. Create a database user and copy the connection string — this is your
   `MONGO_URL`.
3. Under Network Access, allow access from anywhere (`0.0.0.0/0`) unless
   you want to pin Render's static outbound IPs (paid Render feature).

## 2. Backend — Render

`render.yaml` at the repo root is a Render Blueprint — in the Render
dashboard, "New +" → "Blueprint", point it at this repo/branch, and it
provisions the `advisorypro-api` web service from that file.

After it's created, fill in the secrets it left blank (`sync: false` in
`render.yaml` means "set this manually in the dashboard, don't store the
value in git"):

- `MONGO_URL` — from step 1
- `OPENAI_API_KEY`, `STRIPE_API_KEY`, `STRIPE_WEBHOOK_SECRET`
- `PAYFAST_MERCHANT_ID`, `PAYFAST_MERCHANT_KEY`, `PAYFAST_PASSPHRASE`
- `RESEND_API_KEY`, `ADMIN_EMAIL`

`JWT_SECRET` is auto-generated by the blueprint (`generateValue: true`) —
no action needed. `CORS_ORIGINS` is already pinned to
`https://advisorypro.co.za,https://www.advisorypro.co.za`.

Once deployed, Render gives you a URL like
`https://advisorypro-api.onrender.com`. In Render → Settings → Custom
Domains, add `api.advisorypro.co.za` — it'll give you a CNAME target to
add at your registrar (step 4).

Note: the `disk` block in `render.yaml` gives receipt uploads a
persistent 1GB volume so they survive redeploys — this requires a paid
instance type (the blueprint already sets `plan: starter`, which
qualifies).

## 3. Frontend — Vercel

`frontend/vercel.json` configures the build. In the Vercel dashboard,
"Add New" → "Project", import this repo, set the project root to
`frontend/`.

Set one environment variable in the Vercel project settings:

- `REACT_APP_BACKEND_URL` = `https://api.advisorypro.co.za`

This bakes into the static build at build time, so redeploy after setting
or changing it (Vercel does this automatically on the next push, or
trigger a manual redeploy).

Then in Vercel → Settings → Domains, add `advisorypro.co.za` and
`www.advisorypro.co.za` — it'll give you the DNS records for step 4.

## 4. DNS at your registrar

Add the records Render/Vercel gave you above. Typically:

| Host                    | Type          | Points to                          |
|-------------------------|---------------|-------------------------------------|
| `advisorypro.co.za`     | A or ALIAS    | Vercel's apex IP/target             |
| `www`                   | CNAME         | `cname.vercel-dns.com`              |
| `api`                   | CNAME         | `advisorypro-api.onrender.com`      |

SSL certificates are issued automatically (Let's Encrypt) once DNS
propagates — no manual cert work.

## 5. Payment webhooks

Once the domain is live, update webhook URLs in each provider's
dashboard to point at the real domain:

- Stripe: `https://api.advisorypro.co.za/api/webhook/stripe`
- PayFast: set the ITN (Instant Transaction Notification) URL to
  `https://api.advisorypro.co.za/api/payfast-notify` (`backend/routes/payments.py`)

## 6. Smoke test

- `https://api.advisorypro.co.za/api/health` → `{"status": "healthy", ...}`
- `https://advisorypro.co.za` loads and can log in / hit the API (check
  the browser network tab for CORS errors if not — it means
  `CORS_ORIGINS` on Render doesn't exactly match the origin the browser
  sent)
